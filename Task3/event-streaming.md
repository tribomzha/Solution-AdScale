# Схема 

| Критерий                                   | Avro + Schema Registry                              | JSON                                                               |
| ------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------------------ |
| Формат передачи                            | Бинарный                                            | Текстовый                                                          |
| Размер сообщения                           | Обычно меньше                                       | Обычно больше из-за названий полей                                 |
| Читаемость человеком                       | Низкая без декодирования                            | Высокая                                                            |
| Наличие строгой схемы                      | Обязательно                                         | Необязательно                                                      |
| Проверка события до публикации             | Да, через сериализатор и registry                   | Только если отдельно внедрить JSON Schema                          |
| Типизация                                  | Строгая                                             | Слабее без JSON Schema                                             |
| Совместимость версий                       | Контролируется registry                             | Требует собственных правил или registry                            |
| Добавление новых полей                     | Безопасно при наличии `default`                     | Обычно просто, но consumer может интерпретировать поле неправильно |
| Изменение типов                            | Блокируется проверкой совместимости                 | Часто обнаруживается только во время обработки                     |
| Генерация классов                          | Есть                                                | Обычно используется ручная модель или генерация по JSON Schema     |
| Скорость сериализации                      | Обычно выше                                         | Обычно ниже                                                        |
| Нагрузка на сеть                           | Ниже                                                | Выше                                                               |
| Удобство отладки                           | Ниже                                                | Выше                                                               |
| Удобство интеграции                        | Требуется Avro-библиотека и доступ к registry       | Поддерживается почти любым языком                                  |
| Зависимость от инфраструктуры              | Schema Registry становится обязательным компонентом | Plain JSON не требует дополнительной инфраструктуры                |
| Подходит для высоконагруженного потока     | Да                                                  | Да, но менее эффективно                                            |
| Риск неконтролируемого изменения контракта | Низкий                                              | Высокий без схемы                                                  |
**Avro + Schema Registry** можно выбрать, потому что:

1. Событий показов потенциально будет много.
2. Размер сообщения влияет на Kafka и сеть.
3. Одно событие будут читать несколько независимых consumer.
4. Схема будет развиваться.
5. Нельзя синхронно обновлять все producer и consumer.
6. Ошибки в полях кампании, креатива и идентификаторах будут портить статистику.
7. Потребуется replay старых событий.
8. Строгий контракт важнее удобства ручного просмотра.

JSON стоит выбрать, если:

1. Это MVP с небольшой нагрузкой.
2. События читает один consumer.
3. Структура ещё активно меняется.
4. Нет возможности развернуть и поддерживать Schema Registry.
5. Важна максимальная простота подключения разных систем.
6. Потеря части статистики или ошибки формата не имеют серьёзных последствий.

## Арх решение

|Параметр|Выбор|
|---|---|
|Основной формат Kafka-событий|Avro|
|Управление схемами|Schema Registry|
|Режим совместимости|`BACKWARD_TRANSITIVE`|
|Формат внешнего tracking API|JSON или HTTP-параметры|
|Формат внутри Kafka|Avro|
|Просмотр событий|Kafka UI с поддержкой Schema Registry|
|Plain JSON в Kafka|Только для прототипа или некритичных интеграций|

# Consumer groups

|Consumer group|Функция|
|---|---|
|`ad-interactions-storage-v1`|Сохраняет сырые показы и клики|
|`ad-interactions-analytics-v1`|Рассчитывает CTR и агрегаты|
|`ad-interactions-fraud-v1`|Ищет подозрительные показы и клики|
|`ad-interactions-campaign-limits-v1`|Считает лимиты и расход кампаний|
|`ad-interactions-dlq-v1`|Обрабатывает ошибочные события|

# Хранение

| Данные            | Kafka retention | Долговременное хранение |
| ----------------- | --------------: | ----------------------: |
| Показы и клики    |       7–14 дней |            6–12 месяцев |
| Минутные агрегаты |      30–90 дней |                1–3 года |
| DLQ               |         30 дней |              до разбора |
