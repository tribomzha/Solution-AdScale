Таблица факторов и соотвествующего стиля

| Фактор                                          | Выбор             |
| ----------------------------------------------- | ----------------- |
| Команда до 35 человек                           | модульный монолит |
| Жесткий дедлайн по подключению первого партнера | модульный монолит |
| Нет DevOps-инфраструктуры                       | модульный монолит |
| Разные технологии в компонентах                 | модульный монолит |

Почему не просто монолит или микросервисы:
- не монолит потому что система зажата ограничеями данной архитектуры, требуется гибкое мастабирование критичных сервисов, происходит конкуренция за compute между core фуникцоналом и поддерживающим, что сказывается на качестве
- не микросервисы, потому что команда небольшая, нет DevOps-инфраструктуры и соотвествущих практи/бизнес-процессов внутри компании, не все компоненты высокозагружены и требуеют жесткой ихоляции по ресурсам 

Стратегия эволюции
Т.к. приложение работающее, то в качестве паттерна эволюции предлагается Strangler Fig с переходным этапом в виде модульного монолита и выделением критичных модулей в отдельный сервис/набор сервисов
