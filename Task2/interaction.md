Внутреннее взаимодействие:
1 gRPC является тяжелым протоколом с точки зрения разработки, но быстрым с точки зрения работы, поэтому его имеет смысл использовать только в работе критичных интеграций: AD-Auction, Delivery-Auction
2 REST - тяжелее с точки зрения производительности, но проще с точки зрения разработки, поэтому его стоит использовать в некритичных для скорости/производительности интеграциях, так же в интеграциях с высокой изменчивостью: API Gateway - Adviser Cabinet, Adviser Cabinet - Analytics, Analytics - Stats
3 Асинхронное взаимодействие предполагается применять в некритичных для бизнес-процессов сценариях, таким сценарием является сбор и сохранение статистики.

Внешние интеграции:
1 все внешние интеграции происходят по REST, т.к. в данном случает поддержка и тестирование должны быть упрощены. Для Интеграции с DSP можно так же использовать OpenRTB 2.6
2 входящие интеграции проходят через API Gateway для: балансировки, управлением доступа, мониторинга, реализацию Circuit Breaker
